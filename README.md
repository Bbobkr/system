# نظام إدارة مخزون ومبيعات (PHP + MySQL)

نظام كامل لإدارة المخزون والمبيعات — منتجات، تصنيفات، فروع متعددة، مخزون وتحويلات بين الفروع، عملاء وموردون، فواتير بيع وشراء مع طباعة ومرتجعات، باركود، مستخدمون وصلاحيات، تقارير ولوحة تحكم برسوم بيانية. واجهة عربية (RTL) وإنجليزية (LTR). مبني بـ PHP خام + MySQL بدون أي إطار عمل ثقيل أو خطوات بناء (build steps)، ليعمل مباشرة على استضافة هوستنغر المشتركة.

## هيكل المشروع

```
public_html/       ← جذر الموقع (يُرفع محتواه كما هو إلى public_html في هوستنغر)
├── app/           ← الإعدادات ومنطق التطبيق — محمي بـ .htaccess من الوصول المباشر
│   ├── config/    (config.php, db.php, env.php [غير مرفوع لـ git], env.php.example)
│   ├── includes/  (auth.php, csrf.php, functions.php, header.php, footer.php ...)
│   ├── modules/   (product, stock, sales, purchases, report ...)
│   └── lang/      (ar.php, en.php)
├── sql/           ← schema.sql و seed.sql — محمي بـ .htaccess أيضًا
└── (صفحات الموقع: dashboard.php, login.php, products/, sales/, ...)
```

> **لماذا `app/` داخل `public_html`؟** لوحة File Manager في هوستنغر تعرض مجلد الدومين فقط،
> لذا وُضع `app/` و`sql/` بداخله مع ملف `.htaccess` يمنع الوصول لهما عبر المتصفح
> (`Require all denied`) — وهو ما يوفّر نفس الحماية عمليًا.


## التشغيل محليًا (XAMPP / Laragon)

1. ثبّت XAMPP أو Laragon (يوفر PHP + MySQL + Apache).
2. أنشئ قاعدة بيانات فارغة (مثلًا `inventory_db`) عبر phpMyAdmin.
3. استورد بالترتيب: `sql/schema.sql` ثم `sql/seed.sql`.
4. انسخ `app/config/env.php.example` إلى `app/config/env.php` وعدّل بيانات الاتصال المحلية إذا لزم (القيم الافتراضية تناسب XAMPP: `localhost` / `root` / بدون كلمة مرور).
5. اجعل `public_html/` جذر الموقع في خادمك المحلي (أو ضع المشروع كاملًا داخل `htdocs` واجعل `APP_URL` في `env.php` يشير لمسار `public_html`، مثل: `http://localhost/inventory/public_html`).
6. افتح الموقع في المتصفح → افتح `setup.php` (مثال: `http://localhost/inventory/public_html/setup.php`) لإنشاء حساب المدير الأول.
7. **مهم جدًا**: بعد إنشاء الحساب، احذف `public_html/setup.php` من الخادم فورًا — هذا الملف يعمل فقط عند عدم وجود أي مستخدم بعد، لكن حذفه يمنع أي محاولة وصول له مستقبلًا.
8. سجّل الدخول من `login.php` وابدأ بإضافة التصنيفات والمنتجات والفروع.

## النشر على استضافة هوستنغر (استضافة مشتركة)

1. **قاعدة البيانات**: من hPanel → Databases → أنشئ قاعدة بيانات MySQL ومستخدمًا مخصصًا له صلاحية كاملة عليها. احفظ اسم القاعدة/المستخدم/كلمة المرور (عادة `DB_HOST` على هوستنغر هو `localhost`).
2. استورد `sql/schema.sql` ثم `sql/seed.sql` عبر phpMyAdmin (من نفس الصفحة في hPanel).
3. **رفع الملفات** عبر FTP (FileZilla) أو File Manager في hPanel:
   - ارفع **محتويات** مجلد `public_html/` من المشروع (بما فيها `app/` و`sql/`) → داخل `public_html` الخاص بالدومين على هوستنغر.
   - لا حاجة لإنشاء أي مجلد خارج `public_html` — الحماية تتم عبر ملفات `.htaccess` الموجودة داخل `app/` و`sql/`.
4. على الخادم، أنشئ `app/config/env.php` (انسخه من `env.php.example`) واملأ بيانات الاتصال الحقيقية بقاعدة بيانات هوستنغر بالإضافة إلى `APP_URL` (رابط الدومين الكامل) و `APP_DEBUG` = `false`.
5. **لا ترفع أبدًا** ملف `app/config/env.php` الخاص بالتطوير المحلي إلى الخادم — أنشئ نسخة جديدة عليه مباشرة ببيانات الإنتاج.
6. اضبط صلاحيات الملفات: المجلدات 755، الملفات 644، ومجلد `public_html/assets/uploads/products` قابل للكتابة (755 كافية عادة، تجنب 777).
7. من hPanel فعّل شهادة SSL المجانية، و`.htaccess` الموجود في `public_html/` يفرض HTTPS تلقائيًا بعد تفعيلها.
8. اضبط إصدار PHP في hPanel (PHP 8.1 أو أحدث) ليطابق ما تم تطويره عليه.
9. افتح `https://yourdomain.com/setup.php` لإنشاء حساب المدير الأول، ثم **احذف `setup.php` فورًا** من الخادم.
10. اختبر: تسجيل الدخول، إضافة منتج بباركود، عملية بيع كاملة، طباعة فاتورة، لوحة التحكم والرسوم البيانية، تبديل اللغة.

## ملاحظات أمنية

- كل الاستعلامات تستخدم PDO Prepared Statements، وكل نموذج محمي بـ CSRF token، والصلاحيات (RBAC) تُفرض من جهة الخادم على كل صفحة وليس فقط بإخفاء الروابط.
- مجلد الرفع `public_html/assets/uploads/products` معطّل فيه تنفيذ PHP عبر `.htaccess` لمنع رفع ملف ضار متخفٍ كصورة.
- غيّر `APP_DEBUG` إلى `false` دائمًا في الإنتاج لإخفاء تفاصيل الأخطاء عن الزوار (تُسجَّل في `app/php-error.log` بدلًا من ذلك).
- الأدوار الثلاثة (مدير النظام، مدير فرع، موظف) مضبوطة مسبقًا في `sql/seed.sql`، ويمكن تعديل صلاحيات كل دور من صفحة "المستخدمون → الصلاحيات" (تظهر فقط لحساب المدير).

## بيانات الدخول الافتراضية

لا يوجد حساب افتراضي مضمّن لأسباب أمنية — يُنشأ حساب المدير الأول من صفحة `setup.php` عند أول تشغيل (راجع الخطوات أعلاه).
